# Phase 3 — P3b TXL-PBC Pooled + LOSO Benchmark Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tooling to train/evaluate 5 arms (d_both, d_sigma, circlenet, yolo26m, frcnn) × 5 TXL-PBC splits (pooled + 4 LOSO) × 3 seeds on Mickie's Windows GPU, and summarise pooled / LOSO / Δ with paired bootstrap comparisons.

**Architecture:** Every arm writes the same run-dir contract as run_m2 (`summary.json`, `sweep_val.json`, `preds_val.json`, `preds_test.json`, `summary_test.json`, `metrics.jsonl`) under `runs/p3b_<split>_<arm>_s<seed>/`, so `compare_runs.py` works per split with `--prefix p3b_<split>_` and the new `summarize_loso.py` reuses `compare_runs.load_run` / `gate`. A generic runner (`run_exp.bat` / `.sh`) picks the family by arm name. Baselines live in `scripts/baselines/`.

**Tech Stack:** Python 3.11, torch/torchvision (Faster R-CNN), Ultralytics (YOLO26m; Windows only, lazy import), numpy, pytest, cmd + bash.

**Spec:** `docs/specs/2026-10-30-phase3-design.md` §3

## Global Constraints
- Splits: `splits/pooled.json`, `splits/loso_{BCCD,BCDD,PBC,Raabin}.json` (already produced by `prepare_data.py`; never regenerated here). Split names in the runner: `pooled loso_BCCD loso_BCDD loso_PBC loso_Raabin`.
- Run dir: `<runs-dir>/p3b_<split>_<arm>_s<seed>`; arms `d_both d_sigma circlenet yolo26m frcnn`; seeds `0 1 2`.
- DC-CellNet: `epochs_max: 150`, `patience: 30`, `select_from_epoch: 0`, `batch: 8`, AMP, augmentation from base.yaml unchanged; `model.pretrained: true`, `model.heads.density: false`, `loss.cc.enabled: false`. d_both = adaptive σ + stride 2; d_sigma = adaptive σ stride 4; circlenet = radius σ stride 4.
- YOLO26m: epochs 150, patience 30, batch 8, imgsz 640, seed = run seed, Ultralytics defaults otherwise.
- Faster R-CNN: torchvision `fasterrcnn_resnet50_fpn` COCO-pretrained, epochs 50, patience 10 on val mAP50-95, batch 4, SGD (lr 0.005, momentum 0.9, weight_decay 1e-4), linear warmup over the first 1000 iterations from factor 0.001, MultiStepLR ×0.1 at epochs 32 and 42 (torchvision reference 16/26, 22/26 scaled to 50), AMP on CUDA.
- Threshold: every arm `evaluate.py --sweep-thr` on val, test evaluated at that `best_thr` with `--map-ci-n 0` (CI offline in `summarize_loso.py`).
- Class order everywhere: 0 RBC, 1 WBC, 2 Platelets (NOT TXL's `classes.txt` order, which is 0 WBC, 1 RBC, 2 Platelet).
- Every run dir has `summary.json` with at least `best_epoch` (0-based) and `select_from_epoch` (0 for all P3b arms) so `compare_runs.load_run` accepts it.
- All scripts run on Windows (pathlib, no shell-specific calls); `ultralytics` is imported lazily inside `main()` only (not installed on the cloud test box).
- `dccnet` package code (model/decode/loss/targets) is not modified.

## Review Focus
1. YOLO export uses the split JSON labels (our order), never TXL's label txt files — a WBC must come out as class 1.
2. Ultralytics nests relative `project` paths under its own runs dir (this produced `runs\detect\runs\yolo26m_pooled` before) — the run dir must be exactly `<runs-dir>/p3b_<split>_yolo26m_s<seed>` via an absolute `project`.
3. Faster R-CNN on images with zero boxes or degenerate (<1 px) boxes — training must not crash (torchvision asserts positive width/height).
4. Runner resume: a killed run (weights present, no `summary.json`) is renamed aside and retrained; a finished run (`summary_test.json`) is skipped; the YOLO family's aborted marker is `weights/` without `summary.json`.
5. `summarize_loso.py` with missing runs/folds: reports INCONCLUSIVE / blank cells with a warning, never crashes, never silently averages fewer folds.

### Task B5: `summarize_loso.py`

**Files:**
- Create: `dccnet/scripts/summarize_loso.py`
- Test: `dccnet/tests/test_summarize_loso.py`

**Interfaces:**
- Consumes: `compare_runs.discover_runs`, `load_run`, `gate`, `summarize_arm`; `dccnet.eval.coco_eval.coco_map_ci`.
- CLI: `python scripts/summarize_loso.py --runs-dir runs --prefix p3b --data-root data --out reports/p3b.md [--splits pooled,loso_BCCD,loso_BCDD,loso_PBC,loso_Raabin] [--arms d_both,d_sigma,circlenet,yolo26m,frcnn] [--candidate d_both] [--seeds 0,1,2] [--map-ci-n 1000] [--n-boot 1000]`. Writes the markdown report and `<out>.json`.
- Report content:
  1. Per split × arm table: mAP50-95 mean ± sd over seeds (+ 95% CI from `coco_map_ci` pooled over the seed-0 run when `--map-ci-n > 0`), mAP50, per-class AP (from `summary_test.json`), count MAE per class (RBC/WBC/Platelets), recall bins 0–3.
  2. C2 table per arm: pooled mAP50-95, LOSO mean (mean over the 4 folds of the per-fold seed mean), Δ = pooled − LOSO mean. A fold missing any requested seed → that arm's LOSO mean is blank and listed in warnings.
  3. Paired comparisons candidate vs every other arm: (a) pooled split alone, (b) LOSO pooled — per seed, concatenate `abs_err` and `counts` over the 4 folds (fold order fixed: BCCD, BCDD, PBC, Raabin) and run `gate`. Verdict per comparison: GO / NO-GO / INCONCLUSIVE (any missing seed or fold).
  4. Stage-1 line: `pooled stop/go: d_both vs circlenet = <verdict>` (spec §3.2).
